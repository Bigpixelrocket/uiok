# Themes

Every colour UIOK paints is a CSS custom property (a token) such as `var(--accent)`. A theme is a palette of source colours; fixed rules turn that palette into the full token set, and a generated stylesheet declares the tokens for every theme. Switching theme swaps token values only, so no component changes.

## How it works

```text
src/themes/ids.ts           theme ids, names, appearances, root attributes (no colours)
src/themes/catalog.ts       one palette per theme (26 Catppuccin role names, 16 ANSI colours)
src/themes/tokens.ts        the rules: palette -> tokens, and themeStylesheet()
src/themes/themes.generated.css   the output, committed; shipped inside @bigpixelrocket/uiok/styles.css
```

1. `@bigpixelrocket/uiok/styles.css` imports `themes.generated.css`. Its `:root` wears Catppuccin Latte, and Catppuccin Mocha under `prefers-color-scheme: dark`. `:root` also declares `color-scheme: light dark`, so native controls and scrollbars follow the same appearance.
2. A page picks other themes with two attributes on its root element. The light theme's block applies while the system appearance is light, and the dark theme's block while it is dark.
3. Code that reads token values in script (a canvas or a chart) re-reads them when `subscribeThemeChange` calls.

The 18 themes are Catppuccin (Latte, Frappé, Macchiato, Mocha), GitHub Light and Dark, Gruvbox Light and Dark, One Light and Dark, Rosé Pine and Rosé Pine Dawn, Solarized Light and Dark, Tokyo Night and Tokyo Night Day, Nord, and Dracula. Each palette's comment in `catalog.ts` credits its upstream source.

## The attribute contract

| Attribute                       | On                          | Effect                                                                                                                  |
| ------------------------------- | --------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `data-light-theme="<light id>"` | the root element (`<html>`) | that theme's tokens while the appearance is light                                                                       |
| `data-dark-theme="<dark id>"`   | the root element            | that theme's tokens while the appearance is dark                                                                        |
| `data-theme-preview="<any id>"` | any element                 | that theme's preview tokens (`PREVIEW_TOKENS`) inside the element, whatever the page wears; for theme-picker miniatures |
| `data-window-inactive`          | the root element            | the window is not in front: selected text, selected rows, and the active pane's frame grey to quiet tones (below)       |

Without an attribute the defaults apply. Ids are listed in `THEME_ENTRIES`, `LIGHT_THEME_IDS`, and `DARK_THEME_IDS`; validate saved values with `isLightThemeId` and `isDarkThemeId`.

```ts
import { subscribeThemeChange, wearThemes } from '@bigpixelrocket/uiok';

wearThemes(document.documentElement, { light: 'solarized-light', dark: 'nord' });
const stop = subscribeThemeChange(() => redrawCanvas());
```

### An inactive window

macOS greys what is selected in a window that is not in front. A host that knows its window's focus sets `data-window-inactive` on the root while the window is in the background and removes it when the window comes forward (in a desktop shell, from the window's blur and focus events; in a browser, from `window` `blur` and `focus`). Under it the base sheet greys selected text to `--fill`, and the listing greys its selected rows to the quiet fill with words in `--text` and its active pane's frame to `--border-strong`. Without the attribute nothing changes.

```ts
const root = document.documentElement;
window.addEventListener('blur', () => root.setAttribute('data-window-inactive', ''));
window.addEventListener('focus', () => root.removeAttribute('data-window-inactive'));
```

`wearThemes` leaves an attribute alone when it already names the theme, so observers do not fire for no change. Set the attributes before first paint where you can (server-rendered markup, an inline script, or a preload) to avoid a flash of the default theme.

## Tokens by role

Theme tokens differ per theme; fixed tokens are the same in every theme and live on `:root` only.

Every colour has one job. A fill that text sits on is not the colour of a word, and a divider is not a control's outline. So a coloured word reads its text role (`--accent-text`, not `--accent`), a dot or icon reads its mark role, and a field's outline reads `--control-border`. Each role carries a floor that holds in every theme: 4.5:1 for words, 3:1 for marks, outlines, and chart lines.

Words are floored on these grounds: the ground, a panel, the header, a listing, its column strip, and every state ground. The state grounds are the cursor row, the inactive pane's cursor (`--fill`), a hovered panel or listing (`--hover-wash`), a hovered row (`--row-hover`, over the ground, a listing, and a zebra row), a marked row and the cursor on it (over the ground, a panel, and a listing), the current item (over every bare ground), and an edited cell (`--warning-wash` and its strong wash over the ground and a panel). On a state ground a quiet word reads `--text-on-surface`; `--row-meta-text` and `--text-dim` are floored at rest only. A cell or row that changes state paints its tint over an opaque ground (`linear-gradient(var(--marked-cursor-bg), var(--marked-cursor-bg)) var(--ground)`), never over another tint, since each tint is floored over a bare ground. A role used on a ground outside its list has no floor there; add the ground to its rule and to the test table first.

### Retired names

The shadow names and `--switch-knob` are no longer delivered, nor are `--tonal-hover-brightness` and `--success-line`; the grounds and fills below stay, but component stylesheets read their role names. Read the name on the right.

| Retired                                                                                        | Read instead                                                              |
| ---------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `--shadow-menu`, `--shadow-notice`, `--shadow-tooltip`, `--shadow-card`, `--shadow-card-hover` | `--shadow-popover` (a card that sits in the page takes no shadow at rest) |
| `--shadow-dialog`                                                                              | `--shadow-modal`                                                          |
| `--shadow-segment`, `--shadow-knob`                                                            | `--shadow-raised`                                                         |
| `--switch-knob` (white)                                                                        | `--surface` while off, `--on-primary` while on                            |
| `--bg`, `--bg-panel`, `--bg-header` in component stylesheets                                   | `--ground`, `--surface`, `--surface-header`                               |
| `--cursor-bg`, `--cursor-row-bg` in component stylesheets                                      | `--fill`, `--cursor-row`                                                  |

`src/themes/tokens.test.ts` enforces every floor above in every theme through one table of pairings (`PAIRINGS`: each role on each ground a stylesheet draws it on), keeps Latte and Mocha equal to a frozen fixture (`catppuccin-tokens.fixture.json`), and checks that every theme yields the same token names in the same order.

## Changing a theme or a rule

Edit `catalog.ts` or `tokens.ts`, then regenerate the stylesheet:

```sh
UPDATE_THEMES=1 npx vitest run src/themes/themes.test.ts
```

`themes.test.ts` fails while the committed file is stale. A theme overrides a token (`overrides` in its catalog entry) only where it was hand-tuned past what the rule gives, with a comment saying why; `ThemeOverrides` takes a six-digit hex colour for each colour token and refuses compound tokens. Tokens drawn straight from the palette (`--bg-panel`, `--text`, `--primary-hue`, `--group-*`) take no override; change the palette, or `groups` for a group hue. Never regenerate the fixture to make a test pass.

`test/colorLiterals.test.ts` fails on a colour literal anywhere in `src/` outside the token blocks of `themes.generated.css` and the catalog modules.

## Adding an app's own tokens

An app with tokens UIOK does not define (a brand colour, a build-channel tag) derives them from the same themes and writes them through the same generator, so they follow every theme and both appearances under the same selectors:

```ts
import { themeStylesheet, type Theme, type ThemeTokens } from '@bigpixelrocket/uiok';

const css = themeStylesheet({
  includeUiokTokens: false, // the app imports @bigpixelrocket/uiok/styles.css, which already has them
  banner: 'Generated by scripts/app-tokens.test.ts; do not edit.',
  extraFixed: { '--brand': '#ff6600' },
  extraTokens: (theme: Theme, tokens: ThemeTokens) => ({
    '--brand-tint': `color-mix(in srgb, var(--brand) 14%, ${tokens['--bg']})`,
    '--release-tag': theme.appearance === 'light' ? theme.palette.mauve : theme.palette.pink
  }),
  extraBlocks: { "[data-channel='beta']": { '--channel': 'var(--release-tag)' } }
});
```

| Option                       | What it adds                                                                                                                                                                           |
| ---------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `extraFixed`                 | tokens on `:root` that are the same in every theme                                                                                                                                     |
| `extraTokens(theme, tokens)` | tokens per theme, in the default `:root` blocks and in every theme block; `tokens` are the theme's UIOK tokens with overrides applied, and `theme.id` lets the app hand-tune one theme |
| `extraBlocks`                | rules by selector outside any query, after the default `:root`                                                                                                                         |
| `includeUiokTokens`          | `true` (default) writes one combined sheet; `false` writes the app's tokens alone, dropping blocks that would be empty                                                                 |
| `banner`                     | the opening comment                                                                                                                                                                    |

An extra token must be a kebab-case custom property UIOK does not define; the generator throws otherwise, so an app cannot silently change a token UIOK's components read. No value or selector may hold `;`, `{`, `}`, `/*`, or `*/` outside a string or `url()`, nor a string that spans lines, nor the banner `*/`, since each would end its declaration, rule, or comment early. Commit the output and keep it fresh with a staleness test like `src/themes/themes.test.ts`.

### Colour helpers

These helpers from `@bigpixelrocket/uiok` (or `@bigpixelrocket/uiok/themes`) derive new colours inside `extraTokens` the way UIOK's own rules do. They take six-digit lowercase hex colours (`Hex`), the form every palette entry takes, and throw when they read any other form. A theme token is typed as a plain string and some hold `rgb()` or `var()`, so derive from the palette, or pass a token you know holds hex as `Hex`:

| Helper                                     | What it gives                                                                                                                                                                                 |
| ------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `mix(a, b, share)`                         | `share` percent of `a` over `b`, as CSS `color-mix(in srgb)` mixes                                                                                                                            |
| `translucent(hex, opacity)`                | `hex` at `opacity` percent, as `rgb(r g b / opacity%)`                                                                                                                                        |
| `contrast(a, b)`, `luminance(hex)`         | the WCAG 2 contrast ratio (1 to 21) and relative luminance                                                                                                                                    |
| `legibleOn(color, grounds, ratio)`         | `color` when it keeps `ratio` on every ground, else `color` mixed toward black over a light first ground (white over a dark one) just far enough to keep it; black or white when nothing does |
| `firstLegible(candidates, grounds, ratio)` | the first candidate that keeps `ratio` on every ground, else the last; order candidates quietest first                                                                                        |
| `rgbOf(hex)`, `hexOf(rgb)`                 | a colour's channels and back                                                                                                                                                                  |

Use a ratio of 4.5 for text and 3 for a mark read by shape alone, as UIOK's tokens do. A tag whose text must read on its own tinted fill:

```ts
import { legibleOn, mix, themeStylesheet } from '@bigpixelrocket/uiok';

const css = themeStylesheet({
  includeUiokTokens: false,
  extraTokens: (theme) => {
    const tag = mix(theme.palette.peach, theme.palette.base, 18);
    return { '--tag-bg': tag, '--tag-text': legibleOn(theme.palette.peach, [tag], 4.5) };
  }
});
```
